# ModelPilot · dsh-model-assistant

A standalone DSH plugin that turns "a model ID" into a correct, explainable DSH
model entry — and writes it with the smallest possible settings patch.

Everything is field-level: you see exactly which keys will be written, which
warnings fired, and which controls the driver genuinely accepts.

## What it does (MVP)

Adds a **ModelPilot** page to DSH settings (`settings.section`, id
`modelpilot.workbench`) beside the built-in models page:

1. Pick a configured `pi-ai` route (`providers.<id>`).
2. Type the model ID exactly as the gateway expects it (never rewritten).
3. Optionally set display name, `contextWindow`, `maxTokens`, input modalities,
   and reasoning levels.
4. The screen shows the **projected ops** — the literal `settings.mutate`
   operations — plus every warning the engine produced.
5. "写入 DSH 设置" performs a revision-fenced write through the host's own
   `configForms` (`mutate(ops, expectedRevision)`), with automatic conflict
   recovery (re-read + one retry).

## Guarantees it enforces before writing

| Guard | Why |
| --- | --- |
| **R1–R7 reasoning pre-check** | A malformed `reasoningEfforts` dict makes the host refuse the *whole route's* model directory. Bad dicts are refused client-side first: no ops at all. |
| **Catalog-replacement gate** | On a catalog route, writing `models` replaces the entire served directory. The screen lists exactly which model IDs will disappear and requires an explicit checkbox before ops are emitted. |
| **Duplicate-ID refusal** | The host rejects a duplicate `id`; ModelPilot reports the existing index instead of letting the write fail. Case-only collisions warn (host matches literally). |
| **`modelOverrides` ⊕ `models` exclusion** | The two channels are mutually exclusive in `resolveRouteModels`; a write that would violate it is refused up front. |
| **Whitelist projection** | Only `id · name · contextWindow · maxTokens · input · reasoningEfforts` are written. Anything else is dropped with a visible `unknown-key-dropped` warning. |
| **`maxTokens` dual-identity notice** | A model entry's `maxTokens` also becomes that model's default request output budget. The screen says so; it is never silently treated as a pure capability fact. |

## Install

```bash
# from a checkout of this repo
node scripts/build-client.mjs        # regenerate lib/client.js
npm pack                              # -> dsh-model-assistant-0.1.0-alpha.2.tgz
dsh plugin --profile desktop add ./dsh-model-assistant-0.1.0-alpha.2.tgz
```

Then restart DSH (or reload the page) and open **Settings → ModelPilot**.

Supported hosts: `@deepseek-ai/dsh` `>=0.2.0-rc.2 <0.2.2-0`
(peer range is enforced by the host's own `evaluatePluginCompatibility`).

## Development

```bash
npm install
node --test "test/**/*.test.mjs"      # 94 tests
node scripts/build-client.mjs          # rebuild the web half
```

The Web bundle **inlines** the same projection code the Host tests cover
(`src/core/`), so the browser and the tests cannot drift apart. React stays
external — the host's `dsh-client-modules` loader provides it.

Layout:

```
lib/index.js                 Host half (cordis plugin, Config schema, Remote service)
lib/client.js                Web half (generated by scripts/build-client.mjs)
lib/model-assistant-service.js  Remote service (namespace "modelAssistant")
src/core/                    pure domain: identity, candidates, projection, apply, profiles
src/sources/                 models.dev v1 catalog parser
src/client/index.jsx         workbench screen source
src/host/, src/shared/       settings writer / version capabilities (host-side scaffolding)
test/                        unit + integration + bundle-contract tests
docs/                        gap-fill, design (v2), plan, evidence notes, status
```
